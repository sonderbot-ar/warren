# Backlog #175: a structured source for every assumption of a run

Issue: https://github.com/sonderbot-ar/warren/issues/175 · Branch `backlog-175-assumption-sources` · a patch version when merged.

## Problem

The front-end's design principle 2 (`docs/product/design-principles.md`): every figure on screen opens a *Fuente* tab. For a model output that tab shows the run, its *fecha de corte* (as-of date) and the source of each assumption. Today a run's assumptions carry their sources only as English text in `assumptions.method`, written by `trace()` and friends in `domains/analysis/math_engine.py` (for example `revenue [Revenues] 2024-03-31 0000320193-24-000069`). The app would have to parse that text to link a number to its filing, and the text changes whenever the code that writes it does. Only `reported.reported_period` (#140) gives filings as fields today. This serves brief questions 3, 4 and 5 (`docs/product/brief.md`) and F2's first screen (one company and date, the forecast with its range, every number traced to its source).

## What changes

1. **A list of typed sources per assumption row, written when the row is made.** `EngineResult.add(name, value, method, period, sources=[...])` takes the sources beside the method text; every place in `math_engine.py` that adds a row passes them from the same objects it already uses for the text (the `Fact`, the `PricePoint`, the risk-free point, the beta's weeks, the ERP's years, the owner's `UserChoice`). The method text is unchanged, so `reproduce` and `rebuild` are untouched. (Not to be confused with `assumptions.source`, `computed` / `user` / `llm_proposed`, which says who set a row; the new sources say what it was made from.) Six kinds (`domains/analysis/sources.py`); every field is a JSON value, dates as ISO text, numbers raw in their `unit` (no scaling to millions):
   - `filing`: one fact from EDGAR: `item` (Warren's name, e.g. `revenue`), `concept` (the XBRL tag), `unit`, `period_start` (None for a balance), `period_end`, `fiscal_year`, `fiscal_period` (`Q1`–`Q4` or `FY`, as `facts` stores them), `value`, `filed_at`, `accession_no` (None when Warren derived the fact, e.g. Q4 = year − nine months), `inputs` (the accessions a derived fact used), `derived`, `restated`. On a derived fact `concept` is its tags joined by " − ", as `facts` stores it.
   - `market`: one downloaded series: `provider` (`yahoo` or `fred`), `series` (the ticker, the index `^SP500TR`, `DGS10`), `measure`, `start` and `end` (ISO dates; equal for one day; for the ERP's calendar-year returns, Dec 31 of the year before the first, since the first return starts from that close and yield, to Dec 31 of the last). Measures: `close` (price, one day), `splits` (the share-count adjustment from the date the count is on, the cover date for cover-page shares or the filing date for diluted shares, to the price date; and on `price`, the adjustment the download applies), `weekly_total_return` (beta: the stock and the index over the same weeks, two sources), `annual_total_return` (the ERP and its standard error: the index), `yield` (`risk_free`: one day; the ERP: the 10-year yield over its years). Which download: on read, `fetch_sha256` is added from the run's own `runs.price_fetch_sha256` (the ticker), `index_fetch_sha256` (`^SP500TR`) or `yield_fetch_sha256` (`DGS10`), and `url` (the FRED series page, or the Yahoo Finance history page).
   - `owner_choice`: a row of `domains/analysis/user_assumptions.csv`: `choice` (its `name` column, e.g. `erp_method`), `value` (its `value` column as text, e.g. `historical_geometric` or `1989`), `set_by`, `set_on`. The run's own copy, so a later edit of the file doesn't change it (backlog #11).
   - `derived`: computed from other rows of the same run: `inputs` as `[{name, period}]`, each a row the run stores (on a what-if child, an input may carry `run_id`: the parent's row, see item 3). The app follows them to their own sources.
   - `rule`: a value set by a fixed rule with no data behind it: `code` (`not_reported_zero`: an item not reported within a year, counted as zero; `no_debt`: no debt, so the cost of debt is not used; `not_in_annual_report_zero`: a working-capital part the year's 10-K doesn't report, counted as zero). A closed list; a new rule is a code change with a test.
   - `what_if`: only on a what-if child (item 3).
   A row may have several sources (revenue growth: the three 10-K comparatives and terminal growth; the cost of debt: the interest and the debt facts of two years).
2. **Stored in a new table**, migration `0020_assumption_sources.sql`: `assumption_sources (run_id, name, period, position, kind, detail)`, primary key `(run_id, name, period, position)`, a foreign key to `assumptions (run_id, name, period)`, `kind` checked against the six names, `detail` the kind's other fields as one JSON object, `position` the source's place in the row's list from 0. Written by `runs.insert_rows` in the run's own transaction, so a run and its sources are stored together or not at all. (Numbered 0020: M10's branch holds 0018 and #141 took 0019; the runner applies any unrecorded version.)
3. **What-ifs.** A child copies its parent's sources for every row whose value it copies. A row whose value the what-if changed (the `changes[]` of `whatif.revalue`) gets one source of kind `what_if`: `parent_run_id`, `before` (the parent's value, in the row's own unit), `how` (as `revalue` names it: `set` a value, `add` a change, `follows_risk_free`, `follows_terminal_growth`), and `parent_sources`, the parent row's own list, so the tab can say "you changed this; it was X, from this filing". A what-if of a what-if is refused (#141), so `parent_sources` never holds another `what_if`. A copied row is not recomputed in the child (#141 copies it as it is), so when one of its `derived` inputs is a row the child changed, that input gets `run_id: <parent>`: `equity_market_value` after a change of `shares` was computed from the parent's shares, and says so; the same for `debt_tax_rate` after `tax_rate`, and growth rows after `terminal_growth`.
4. **A call and a command.** `domains.analysis.sources.run_sources(conn, run_id) -> RunSources` and `python -m domains.analysis sources --run-id R [--name N] [--json]`. `to_dict()`: `run_id`, `parent_run_id`, `ticker`, `as_of` (the *fecha de corte*), `recorded` (whether the run stored sources), `rows[]` with `name`, `period`, `value`, `sources[]` and `gap` (None when sources are stored), and `outputs[]` (item 7). A `filing` source in the answer adds `filing`: the #140 `Filing` shape (`accession_no`, `form`, `filed_at`, `url` to the EDGAR folder), and `inputs` become `Filing`s too, read from `financial_facts` by accession with the same helper `reported` uses (`reported._Filings`); a `market` source adds `label` (`Yahoo Finance`, `FRED`). A row with no stored source has `sources: []` and `gap` `{code: "not_recorded", params: {}, text}` (runs made before this version; `text` is an English fallback, the app owns the Spanish, as in #140). `recorded` is true when the run has any stored source; since a run's sources are written in its own transaction and `check` refuses a partial set, a run has all or none. Point in time: the call reads only the run's stored rows and the `filings` table by accession; every filing named was public on the run's as-of date because the row was built from a point-in-time query.
5. **Older runs: a backfill.** `python -m domains.analysis sources --backfill (--run-id R | --all)` rebuilds a baseline's rows from its pinned data (`runs.rebuild`, M2.1) and stores the rebuilt sources only when every rebuilt row equals the stored row exactly, value and method (`Rebuild.ok`); otherwise it skips the run and says why (`rebuild_differs`, or the rebuild's own error). The rebuilt sources come from today's code over the same pinned data: the exact-match guard on values and method text is what shows the build took the same path, and the sources are written by the same lines that wrote that text. What-ifs stored before this version are not backfilled (there are only the few made since v0.9.9, and telling `set` from `add` would mean parsing their method text): they answer `not_recorded`. Nothing else in a stored run changes.
6. **A completeness check.** `sources.check(rows, sources)`: every row has at least one source, every `derived` input names a row of the run, every `what_if` is on a child. `save_rows` refuses a run that fails it, so a new kind of row can't be added later without its source.
7. **Outputs are traced too.** A number on screen is often an output (value per share, WACC, a quarter's revenue or FCFF: brief Q3, Q4, Q5). `sources.output_trace(rows)` gives each stored output (`run_outputs`) its `formula` (a code, e.g. `revenue_from_growth`, `ebit_from_margin`, `wacc`, `gordon_terminal_value`) and its direct `inputs`, each `{of: "row" | "output", name, period}`, from `dcf.compute`'s arithmetic; the app follows outputs back to rows, and rows to their sources. It is computed from the run's periods on read (nothing stored), and a test checks it against the arithmetic: moving any row changes only outputs whose trace reaches that row. `run_sources` returns it as `outputs[]` with each output's `value`.

**LLMs.** None. **Numbers.** None change: sources describe rows, they don't move them.

## Design review (nov.04.2026)

Explainer, analyst, and professor with the front-end product-lead's read of *Product impact*, in parallel. Analyst NO-GO (4 blockers), professor NO-GO (1), product-lead NO-GO (2); all accepted.

- **Analyst.** (1) A rescaled seed quarter uses all four quarters of its year (`math_engine.py:267-273`): all five facts are sources. (2) A what-if copies rows without recomputing them (`whatif.py:318-324`), so a copied `derived` source could point at a row the child changed (`equity_market_value` after `shares`): such inputs now name the parent's row (item 3). (3) There is no `filings` table: form and date come from `financial_facts` by accession, as `reported._Filings` does. (4) `roll_years` and an all-missing `debt` had no describable source: `derived` from the last seed quarter, and `rule not_reported_zero`. Ideas taken: both facts of each comparative; cost-of-debt debt facts as `filing` sources; the ERP window starts at the year-end before the first year; the index is `^SP500TR`; `price` lists its split adjustment; the split window's start date; a derived fact's joined concept; a working-capital rule code; owner-choice rows get sources; what-if backfill dropped rather than parsing method text.
- **Professor.** (B) Five kinds in items 1–2 but a sixth in item 3: the CHECK would refuse every what-if source. Now six everywhere. Ideas taken: the PROV-DM mapping and the where-/how-provenance split (*Why this shape*); `assumptions.source` and the new sources told apart.
- **Product-lead.** (B1) Outputs had no structured trace, and brief Q3, Q4 and Q5 are about outputs: item 7 adds `outputs[]` with formula codes and inputs, tested against the arithmetic. (B2) As the professor's. Ideas taken: every code listed for the text catalogues; a `url` on market sources; values raw in `unit`; the backfill runs over every stored baseline before F2 shows a screen.
- **Explainer.** Gaps answered in the text: six kinds; what `choice` and `value` hold; `fiscal_period` values; which measures beta and the ERP use and which hash field; the JSON `detail` and `position`; no grandchildren; `how` values and `before`'s unit; `gap` null when stored; English fallback text; `recorded` is all or none; the backfill's sources come from the code that wrote the matched text; the migration runner's rule (v0.9.9, `shared_kernel/database.py`); where the real-data results go.

## Steps

- **Step 0.** This design doc.
- **Step 1.** `domains/analysis/sources.py` (the kinds, `check`, JSON in and out), migration 0020, `EngineResult.add(..., sources=)` and the sources on every row `build_inputs` makes; `runs.insert_rows` stores them; `save_rows` refuses an incomplete set. Tests (`tests/analysis/test_sources.py`, `tests/shared_kernel/test_migration_0020.py`): every row of the test company's run has a source and every derived input resolves; the seed quarter names its 10-Q accession and tag; a rescaled seed names the year and all four quarters of it (the sum is the denominator); revenue growth names both facts of each same-filing comparative; the cost of debt names the interest and every debt fact of both years (one year when the opening year reports none); owner-choice rows are `owner_choice`; `roll_years` is derived from the last seed quarter (its period end is the base date) and the run's as-of date; debt with every part missing is `rule not_reported_zero`; a child's copied `equity_market_value` after a share change points at the parent's `shares`; `risk_free` names `DGS10` on its date and the run's yield hash; `beta` names the weeks of both series; `erp` names the index and the yield over its years; `terminal_growth` is derived from `risk_free` plus the owner's method; a minority interest not reported is `rule not_reported_zero`; an incomplete set is refused and nothing is stored; the table and its keys exist after 0020 and old runs keep their rows. `reproduce` still passes on every stored test run. Exit: green.
- **Step 2.** What-ifs (item 3), `run_sources`, the output trace (item 7) and the command (item 4). Tests: a child's unchanged rows have the parent's sources; a changed row is `what_if` with `before` and `parent_sources`; terminal growth that followed the risk-free rate says so; `filing` sources carry the form and the EDGAR folder URL; a run without stored sources returns `recorded: false` and `not_recorded` on every row; every output has a trace whose inputs exist; moving each row of the test run by 1% changes only outputs whose trace reaches it, and every output whose trace reaches a value-carrying row moves with it; `--json` is plain JSON. Exit: green.
- **Step 3.** The backfill (item 5). Tests: a run whose sources are deleted gets the same sources back; a run whose rebuilt rows differ is skipped with `rebuild_differs` and nothing stored; a what-if is skipped as `what_if_not_backfilled`. Exit: green.
- **Step 4.** Real data, if the snapshot restores: one new run per company; every row sourced and every filing's accession found in `financial_facts`; `reproduce --all` passes; the backfill over every stored baseline, with counts of filled and skipped runs and why. Results go in a "Real-data check" section at the end of this doc.

**Exit criterion:** all tests and ruff pass; every row of a new run has a structured source; `reproduce` is exact; `docs/team-sync.md` names the fields.

## Alternatives considered

- **Parse `method` on read.** Rejected: the issue asks not to, and the text is English prose that changed between versions (rebuild's `values_ok` exists because it did).
- **Rebuild on every read.** Rejected as the default: it needs the full data, takes seconds, and fails when a concept map changes. Kept as the one-time backfill, with the exact-match guard.
- **Wide columns instead of JSON.** Rejected: six kinds with different fields would leave most columns empty; the kind is a checked column and the fields are validated in code, both ways.
- **One source per row.** Rejected: revenue growth and the cost of debt really have several, and the tab should show all of them.
- **Store the output trace.** Rejected: it follows from `dcf.compute` and the run's periods alone, so storing it would only add a copy that could disagree.

**Why this shape.** It is the W3C PROV model in small (Moreau and Missier 2013, PROV-DM): `filing` and `market` are primary sources, `derived` and the output trace are derivations, `owner_choice` is attribution to an agent, `rule` a plan, `what_if` a revision. It records *where* each number came from (Buneman, Khanna and Tan 2001, "Why and Where"), while *how* the inputs were combined stays in `method` and in the formula codes, on purpose: the *Fórmula* tab teaches the how.

## Product impact

Serves brief questions 3, 4 and 5 and F2's first screen; the *Fuente* tab of design principle 2 can now be built for model outputs. Adds a call `domains.analysis.sources.run_sources(conn, run_id)`, a command `python -m domains.analysis sources`, and a table `assumption_sources`. Fields as in items 1, 3, 4 and 7. Codes the app needs words for: the six kinds, the measures, the rule codes, the `how` values, the formula codes (listed in `sources.FORMULAS`) and `not_recorded`; `item` values are Warren's canonical names (`domains/fundamentals/concept_map.csv`). Nothing renamed or removed; `method` stays as it is (English, for the trace). An output's tab follows `outputs[]` back to the rows. The app asks for sources by run id; `recorded: false` means an older run; the backfill over every stored baseline runs in Step 4, so before F2 shows a screen every stored run that can be rebuilt has sources.

## Real-data check (nov.04.2026)

On the restored snapshot `warren-20261103T070542Z` (895 stored runs; migrations 0019 and 0020 applied on restore).

- **New runs.** One baseline per company as of 2026-10-30 (`AAPL_2026-10-30_1` … `XOM_2026-10-30_1`): 139–143 rows each, every row sourced (`sources.check` passes), 1,174 `filing`, 112 `market`, 576 `derived`, 32 `owner_choice` and 27 `rule` sources in all. Every filing's accession is found in `financial_facts` with its form, none was filed after the as-of date, 101 outputs traced per run, and each run reproduces.
- **Backfill.** `sources --backfill --all`: 895 of 895 older runs rebuilt exactly and got their sources (`filled 895`, `already_recorded 8` for the new runs), none skipped, in 2 min 13 s.
- **Reproduce.** `analysis reproduce --all`: 903 of 903 runs reproduced to the cent.
