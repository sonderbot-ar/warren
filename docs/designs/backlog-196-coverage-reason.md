# Backlog #196 design: the coverage warning as a reason code, and only Warren's warnings in run notes

Issue #196 (front-end, from the #172 design review, `docs/designs/backlog-172-run-warning-codes.md`). Branch `backlog-196-coverage-reason`.

Status: Done (nov.05.2026; v0.9.22, PR #219, merge `c516676`; gatekeeper GO, follow-ups in #218).

## Problem

1. **The coverage warning carries English the app can't translate.** When a query's as-of date is past the day a company's CIK stopped filing (today only Exxon: CIK 0000034088 stops on 2026-08-03 after the holding-company reorganisation), `domains/fundamentals/universe.py:warn_if_beyond_history` raises a `CoverageWarning`. Since #172 it is coded `beyond_history` with params `ticker`, `cik`, `as_of`, `history_ends` and `note`, but `note` is the universe file's English paragraph (`domains/fundamentals/universe.csv`, XOM row). Team sync (v0.9.15) told the app to "leave it out or show it as is until #196". The two facts a student needs, *why* the history stops and *where it continues*, are only in that prose.
2. **Any library warning becomes a stored run note.** `build_inputs` records every warning raised while reading facts (`domains/analysis/math_engine.py`, the `catch_warnings(record=True)` + `simplefilter("always")` block) and `coded_warnings` (`domains/analysis/coded.py`) stores any it doesn't know as `data_warning`, English text only. A library upgrade (a pandas `FutureWarning`, a sqlite3 `DeprecationWarning`) would add untranslatable lines to every new run with no change to Warren. On real data today there are none (0 `data_warning` lines across 903 runs, #172 results), so nothing stored changes.

## Plan

- **Step 0.** This design doc; roadmap line in team sync.
- **Step 1. Reason and successor in the universe file.** `universe.csv` gains three columns, between `history_ends` and `note`: `reason`, `successor_cik` and `successor_name` (the name added at the product lead's request: a CIK alone can't be shown to a student). `COLUMNS` becomes `ticker, cik, history_ends, reason, successor_cik, successor_name, note`. XOM's row: `holding_company_reorganisation`, `0002115436`, `ExxonMobil Holdings Corp` (EDGAR: the 8-K12B succession notice filed 2026-07-01, accession 0001193125-26-291990, analyst check). Validation in `load_universe`, every problem reported at once as now: `reason` must be one of `COVERAGE_REASONS` (a public closed set in `universe.py`, today `{"holding_company_reorganisation"}`, which the app's catalogue test imports) and is required when `history_ends` is set and refused when it is not; a reason in `REASONS_WITH_SUCCESSOR` (today the same one: a holding-company reorganisation always has a successor registrant, Rule 12g-3, professor) needs `successor_cik` and `successor_name`; the two go together; `successor_cik` is empty or ten digits, differs from `cik`, and needs `history_ends`; a pinned `cik` may appear once (analyst: lookups use the first match). A future reason without a successor (a delisting, say) leaves both null and the app drops the "continues under" clause. `UniverseCompany` gains `reason`, `successor_cik` and `successor_name` (all `str | None`, after `history_ends`, keyword use recommended). `DataWarning` (Step 3) is `CoverageWarning`'s base. `CoverageWarning.fields` gains the three (null when empty); `note` stays as the English fallback, and the warning's English text is byte for byte unchanged, so `runs.notes` and the #172 backfill rule (`docs/designs/backlog-172-run-warning-codes.md`: texts joined equal `runs.notes`) still hold. Tests (`tests/fundamentals/test_universe.py`): XOM's reason and successor; each new validation error; a file with the old four columns is refused; the warning's fields carry all three and its text is unchanged; every reason in the file is in `COVERAGE_REASONS`. Exit: tests and ruff pass.
- **Step 2. Stored notes get the fields on read.** Runs stored before this change hold `beyond_history` params without the three keys (`run_notes` table, migration 0021). No migration and no rewrite of stored rows: `runs.run_notes` (the only reader of stored notes; the `notes` command and its `to_dict` go through it) adds them, when absent, from today's universe row matched on the note's own `cik` **and** `history_ends` (`universe.coverage_fields`; analyst: a cut-off since corrected is never paired with another row's reason), plus `filled_on_read: true` so the provenance shows (professor). No match gives the three as null. The params a note was stored with are never changed in the database. Point-in-time: the fill is a label about the company, not a financial number, and it cannot name anything that was not public on the run's date: the note exists only for `as_of >= history_ends` (2026-08-03), and the successor's 8-K12B was public on 2026-07-01 (analyst). `reported_period` warnings are computed live and carry the fields from Step 1. The what-if's `run_warning` wraps only post-valuation checks (`domains/analysis/whatif.py`, `notes = [Coded("run_warning", ...) for check in checks]`), never a build warning, so it is untouched. Tests (`tests/analysis/test_run_notes.py`): a stored note without the keys reads back with them and `filled_on_read`; one with them is returned as stored; an unknown cik, a corrected cut-off or no cik gives nulls; the stored row is untouched. Exit: tests pass.
- **Step 3. Only Warren's warnings become notes.** New `shared_kernel/data_warnings.py` with `class DataWarning(UserWarning)`, the base for warnings Warren raises about the data it reads; `CoverageWarning` subclasses it. `coded_warnings` codes `CoverageWarning` as `beyond_history`, any other `DataWarning` as `data_warning` (text only, as now), and skips every other warning; a new `coded.pass_on(caught)`, called by `build_inputs` and `reported_period` right after their `catch_warnings` block, re-emits those with `warnings.warn_explicit(message, category, filename, lineno, source=...)` (no registry, so the default filter shows each once per call), so they still reach the log and pytest but are never stored. Under `-W error` a library warning would now raise there instead of being swallowed into a note; the repo sets no such filter (analyst; follow-up issue). `data_warning` stays in `RUN_NOTE_CODES` (a future Warren `DataWarning` without its own code, and any line stored before). Tests (`tests/analysis/test_build_warning_codes.py`): the existing "plain warning is a data_warning" test changes, because the behaviour changes on purpose: a plain `UserWarning` is not a note and is re-emitted (`pytest.warns`); a `DataWarning` subclass is a `data_warning` with its text; `beyond_history` carries the two new params. Exit: full suite and ruff pass.
- **Step 4. Results on real data.** With the snapshot restored: find stored XOM runs past the cut-off (`run_notes` rows with code `beyond_history`); `python -m domains.analysis notes --run-id R --json` on one shows the three fields and `filled_on_read`; `reported --ticker XOM --period latest-quarter --as-of 2026-10-30 --json` shows them live; `reproduce --all` passes; `runs.rebuild` on 11 baselines drawn with seed 196 plus the XOM run past the cut-off passes, with that run's rebuilt coverage text equal to its stored one; runs with notes but no `run_notes` rows (never backfilled) are counted, expected 0 (analyst, product lead). Results in "Results on real data" below.

## Alternatives considered

- **Rewrite stored params with a migration.** Changes stored rows for a fact that belongs to the company, not the run; a read-time fill keeps the database as written and gives the same answer. Rejected.
- **Drop `note` from the params.** The English fallback is useful in the log and in the trace; the app ignores it. Kept.
- **Filter warnings with `simplefilter("ignore")` for non-Warren categories.** Hides them completely; a library deprecation that later breaks a query would arrive with no warning. Re-emitting keeps them visible. Rejected.
- **A successor ticker param.** XOM keeps its ticker, so it would repeat `ticker` (product lead). Not added.
- **Successor linking (reading the new CIK's filings).** That is the "later task" the note names; it changes data coverage and is out of this item.

## Product impact

- Serves the first screen (`docs/product/brief.md`, Q3, Q4 and Q14, on an XOM date after 2026-08-03): the coverage warning can be shown in Spanish from `reason` and `successor_cik` with no English. Add `holding_company_reorganisation` to the text catalogue; `COVERAGE_REASONS` is the closed set.
- Adds params `reason`, `successor_cik` and `successor_name` to `beyond_history` (run notes and `reported_period` warnings), and `filled_on_read: true` on a stored note filled from today's universe file. `successor_name` is a proper noun: put it in the Spanish sentence as is. Gloss "CIK" for students ("el número de registro de la empresa ante la SEC", professor). The what-if's `run_warning` never carries `beyond_history`. Nothing renamed or removed; `note` keeps its meaning (English, for the log).
- Fewer English-only lines: a library warning no longer becomes a `data_warning` note on a new run.
- `universe.csv` has two more columns. The question reader reads only `ticker` from it (`webapp/reader/reading.py`, `tickers()`), so it is unaffected.

## Design review

Explainer, analyst, professor and the front-end product lead, in parallel, on the Step 0 doc (nov.05.2026). No blockers from the analyst or the professor; the product lead's one blocker and the explainer's four gaps are fixed above.

- **Product lead.** Blocker: a successor CIK can't be shown to a student; add the name (`docs/product/design-principles.md`, plain language and no text hard-coded in logic). Accepted: `successor_name` column and param. Ideas taken: keep `COVERAGE_REASONS` public for the app's catalogue test; count never-backfilled runs; say what a null successor means; drop the what-if claim. No breakage: the reader reads only `ticker` from `universe.csv`.
- **Analyst.** GO. EDGAR confirms the 8-K12B on 2026-07-01 and the cut-off; no look-ahead; reproduce, rebuild and the backfill rule are untouched by notes. Ideas taken: fill only when `history_ends` matches; refuse a CIK pinned twice; count never-backfilled runs; correct the what-if claim. Idea filed: a test for `pass_on` under `-W error`.
- **Professor.** No blockers; matches the CRSP/Compustat practice of a permanent entity link across identifier changes (Shumway 1997 on uncoded endings; Alphabet's 2015 reorganisation as the precedent). Ideas taken: `filled_on_read`; a successor required for a reorganisation. Ideas filed: an `event_date` param (why the history stops a month after the reorganisation), and modelling a second reason on CRSP's delisting-code families (`successor_issuer`) when one is needed.
- **Explainer.** Gaps fixed: how other warnings come back (`pass_on`), why the fill is point-in-time safe, the what-if path, Step 4's commands and sample, where the fill applies, the test files and the doc links.
