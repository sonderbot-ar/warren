# Backlog #141: what-if revaluation, a stored run revalued with named inputs changed

Issue: https://github.com/sonderbot-ar/warren/issues/141 · Branch `backlog-141-what-if` · Version v0.9.9 when merged.

## Problem

The front-end team's request R2a (brief questions 7 and 8, `docs/product/brief.md` §5; the owner, oct.30.2026: students learn by changing one input and watching the ripple). Today a student who asks "if Walmart's operating margin falls one point, how much does its value per share change?" can only get one number from a hand-written shock file through the Monte Carlo (`python -m domains.analysis simulate`). That number is not stored as a valuation, cannot be shown line by line, and runs through shock sizing, which is calibrated separately (#73). There is no stored, linked, reproducible revaluation a screen can call, and no way at all to move the risk-free rate, beta, debt or shares.

## What changes

A new call, `domains.analysis.whatif.revalue(conn, run_id, changes) -> WhatIf`, and a command, `python -m domains.analysis whatif --run-id R --set NAME[@PERIOD]=VALUE --add NAME[@PERIOD]=DELTA [--json]`.

1. **The inputs a student may change.** The six drivers of `dcf.DRIVERS` (`revenue_growth`, `operating_margin`, `tax_rate`, `da_pct`, `capex_pct`, `nwc_pct`), each for one forecast period or, without a period, for all eleven; and these single values of `dcf.SINGLE_VALUES`: `risk_free`, `beta`, `erp`, `cost_of_debt`, `terminal_growth`, `debt`, `cash_and_investments`, `shares`. Left out on purpose: `equity_market_value` (a market price, not a view; it is the WACC's equity weight), `debt_tax_rate`, `minority_interest`, `roll_years` and `revenue_seed` (facts of the base date, not assumptions). A change is either `set` (the new value) or `add` (a shift added to the stored value), in the row's own unit: fractions for rates and shares of revenue (0.01 = one point), whole currency units for money, a count for shares. An unknown name, a period the run does not have, a period on a single value, or two changes to the same row is refused with a code.
2. **Range checks before any arithmetic.** `shares` must stay positive; `debt`, `cash_and_investments` at or above zero; `tax_rate` in [0, 1); `revenue_growth` above −1. `financial_math` already refuses the rest (cost of capital at or below terminal growth, a non-positive rate) and its reason code is passed on. A refused what-if stores nothing.
3. **Terminal growth follows the risk-free rate when the run says so.** Every run so far stores the owner's choice `terminal_growth_method = risk_free` (terminal growth equals the risk-free rate, `math_engine.py`). When the student changes `risk_free` and does not also change `terminal_growth`, and the run's choice is `risk_free`, the child's terminal growth moves to the new risk-free rate, and the row records why (`follows_risk_free`). If the student also sets terminal growth, theirs wins. A run whose choice is anything else keeps its terminal growth. This is a property of the run, not a new rule: a future choice of method would bring its own rule here.
4. **A linked child run.** The child copies every assumption row of the parent and replaces only the changed ones, each with source `user` and the method text `what-if on <parent>: <how> (was <old value>)`. It is stored with `runs.save_run`'s tables (`runs`, `assumptions`, `run_outputs`, `run_output_gaps`), under the id `<parent>_whatif_<n>`, with the parent's data snapshot hashes (its rows came from the same data) and a new column `runs.parent_run_id` (migration 0019). Because a run's outputs are a pure function of its rows (`dcf.outputs_and_gaps`), the child reproduces to the cent with the existing `reproduce`; nothing in the invariant changes. A child's `rebuild` is refused with a clear message: its rows are not meant to match the data; rebuild the parent. A child cannot be the parent of another what-if (refused, `parent_is_what_if`): the app sends the whole list of changes against the original run, so every child is one step from data. Asking the same changes again returns the stored child (`reused: true`) instead of storing a copy.
5. **Children stay out of baseline lookups.** The two places that look up "the baseline run for this company and date" (`orchestration/nodes.py:build_baseline`, `llm/__main__.py:_baseline_run`) add `parent_run_id IS NULL`, so a pipeline run or an AI proposal is never sized on a student's what-if. `save_run`'s numbering counts baselines only.
6. **What the call returns.** `WhatIf.to_dict()`: `run_id` (the child), `parent_run_id`, `ticker`, `as_of`, `currency`, `reused`, `terminal_method` (`gordon_fcff` or `value_driver_ronic_wacc`) with `terminal_formula` (a coded: `gordon`: TV = FCFF × (1 + g) / (WACC − g); `value_driver`: TV = NOPAT × (1 + g) / WACC, so with RONIC = WACC growth adds no value and a rate change moves value mostly through WACC, the issue's product note), `changes[]` (each row changed: `name`, `period`, `before`, `after`, `how` in `set`, `add`, `follows_risk_free`), `lines[]` (before and after for `cost_of_equity`, `wacc`, `terminal_growth`, `pv_explicit`, `terminal_value`, `pv_terminal`, `enterprise_value`, `terminal_share`, `equity_value`, `value_per_share`, and `fcff` for each of the eleven periods: `name`, `period`, `unit`, `before`, `after`, `change`, `change_pct`), `notes[]` (codeds: the parent's post-check warnings that the child adds, e.g. a thin WACC − growth spread; `no_value` for an ERP ± 1 SE bound that has none). Every difference and percentage is computed here through `financial_math` (`fm.growth`), so the app does no arithmetic (Decision 13, principle 5). `change_pct` is None when the before value is zero or negative (`fm.growth` refuses a non-positive base).

**Point in time.** The call reads no data: it revalues the parent's stored rows, which were point in time on the parent's date. The child has the parent's `as_of`. Nothing it computes is newer than the parent.

**LLMs.** None. The student (or the app's question reader, Decision 9, which only labels a question) names the input and the size; the engine does every number.

**Migration order.** The M10 branch (draft PR #129) holds migration 0018 and the restored data already carries it. This item takes 0019, and the migration runner changes from "apply every version above the highest applied" to "apply every version not yet recorded", in order, so 0018 still applies on a database that got 0019 first. A test covers a database with 0017 and 0019 applied then getting 0018.

## Alternatives considered

- **Go through `shocks.apply`** (the issue suggests it where it fits). Rejected for storage: a shock moves `Inputs` in memory by a time shape in points or basis points, while a what-if must be stored as rows so the existing `reproduce` checks it, and it has no time shape (a value per period, or the same for all). A flat change through a 20-quarter shape would give the same driver path for the drivers it covers, but not for `risk_free`, `beta`, `debt` or `shares`, which shocks do not move. Editing rows directly is simpler and covers all.
- **Store only the changes on the child and rebuild the rest from the parent.** Rejected: reproduce would need to know about parents, and a child would break if the parent were ever deleted. Copying every row keeps "a run is its rows".
- **Allow a what-if of a what-if.** Rejected for now: chains make the "before" ambiguous and terminal-growth following harder to read. The app re-sends the full list.
- **A separate table for children instead of a column.** Rejected: every reader of `runs` (reports, reproduce, hindsight, ranges) then works on a child for free, which the front-end wants (a child's ranges and report work like any run's).
- **Renumber M10's migration.** Rejected: the shared data snapshot already records 0018 as M10's.

## Product impact

Serves brief question 8 fully (Sí) and question 7 in part: a student can move the risk-free rate and see WACC and value move, but "the Fed raises 25 bp" still needs the transmission to the 10-year yield (R2c, #143); until then the app must label a risk-free change as "if the 10-year yield moved by X", a hypothetical. Unblocks R2b (#142, the two-input grid, which is many what-ifs). No existing output, name or field changes; runs gain a nullable `parent_run_id`.

Adds `domains.analysis.whatif.revalue(conn, run_id, changes)` with `Change(name, value=None, delta=None, period=None)` (exactly one of value and delta), `WhatIf.to_dict()`, `WhatIfError` (`code`, `params`, `text`), and the command `whatif`. Fields of `to_dict`:

- top: `run_id`, `parent_run_id`, `ticker`, `as_of`, `currency`, `reused`, `terminal_method`, `terminal_formula` (coded), `changes[]`, `lines[]`, `notes[]` (codeds);
- a change: `name`, `period` (`-` for a single value), `before`, `after`, `how` (`set`, `add`, `follows_risk_free`);
- a line: `name`, `period`, `unit` (`fraction`, a currency, or `per_share` in currency), `before`, `after`, `change` (after − before), `change_pct` (fraction, or None on a non-positive base);
- refusal codes: `unknown_input`, `not_changeable`, `unknown_period`, `period_on_single_value`, `duplicate_change`, `value_and_delta`, `out_of_range` (params `name`, `low`, `high`, `value`), `parent_is_what_if`, `no_run`, and `financial_math`'s reasons (`growth_not_below_rate`, `rate_not_positive`, `rate_not_above_minus_100`, `invalid_input`);
- note codes: `terminal_growth_follows_risk_free`, `run_warning` (a post-check of the child, English text), `no_value`.
